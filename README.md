# iCon Conference App

A lightweight conference management platform designed to solve real attendee pain points—reducing missed sessions, enabling meaningful connections, and streamlining event coordination.

🔗 **Live Demo:** [ibeech22.github.io/iConApp](https://ibeech22.github.io/iConApp/)

---

The **Howard University Alumni Retreat** is a multi-day professional conference connecting alumni and current college students (juniors and above). In 2024, we faced three critical challenges:

1. **Missed Sessions:** Attendees relied on email schedules, leading to confusion about session times and room locations. People were showing up to the wrong rooms or missing sessions entirely.

2. **Limited Networking:** Connecting with other attendees was hit-or-miss—if you didn't catch someone during a break and exchange contact info, the opportunity was lost. There was no systematic way to discover and connect with fellow attendees.

3. **Existing Solutions Fell Short:**
   - **Third-party conference apps** required expensive subscriptions ($500-$2,000+) for a single event
   - **WhatsApp groups** worked for announcements but couldn't manage schedules, collect structured feedback, or facilitate discovery
   - **Email blasts** were one-way, static, and easily overlooked

We needed a simple, cost-effective solution purpose-built for our community.

---

## 💡 The Solution

**iCon** is a no-frills conference management web app that delivers exactly what attendees need:

### Core Features (MVP Launch - 2025)
- ✅ **Real-Time Agenda Management:** Live schedule updates with session details, times, and room locations—no more digging through emails
- ✅ **Attendee Profiles:** Searchable directory enabling attendees to discover and connect with each other before, during, and after the event
- ✅ **Feedback Collection:** Post-event surveys to capture user sentiment and inform future iterations

### Why It Works
- **Accessible:** Web-based (no app store download required)
- **Simple:** Intentionally minimal feature set based on user feedback—attendees wanted "something that just works"
- **Fast to Deploy:** Built and launched in under 6 months as a solo founder

## 🛠️ Product Journey

### Phase 1: Discovery (2024)
- Attended the 2024 retreat and observed friction points firsthand
- Created initial concept and mockups
- Conducted informal user interviews with alumni and students
- **Key Insight:** Users didn't want complexity—they wanted a lightweight tool that solved specific problems

### Phase 2: MVP Development (2024-2025)
- Initially explored hiring engineers, but cost constraints led to a pivot
- Leveraged **Glide** (web app platform) to build MVP solo, keeping costs near-zero
- Launched pilot at 2025 retreat with core features only

### Phase 3: Iteration & Feedback (Post-2025 Launch)
Collected structured feedback from 50+ users:
- **45%** requested in-app chat/messaging feature
- **30%** wanted enhanced profile customization (professions, resumes, LinkedIn integration)
- **15%** requested live session ratings and individual feedback forms

### Phase 4: Scaling (2026 Roadmap)
Currently developing a more robust version with:
1. **In-app messaging** (highest-priority feature based on user feedback)
2. **Enhanced attendee profiles** with professional details and resume sharing
3. **Native app deployment** (iOS/Android) for improved reliability and offline access
4. **Live session feedback** to enable real-time event optimization

## 🎯 Critical User Journeys

Understanding how attendees interact with iCon was central to the MVP design. Here are the core user flows, prioritized by impact:

### P0 (Must-Have) Journeys

**1. Navigate to Agenda**
- **User Need:** Quickly find what session is happening now and where
- **Flow:** Open app → View live agenda → See session details (time, room, description)
- **Why P0:** Solves the #1 pain point—missed sessions due to email confusion
- **Success Metric:** 40% reduction in missed sessions validates this was the right priority

**2. Create Profile**
- **User Need:** Join the attendee directory to be discoverable by other participants
- **Flow:** First login → Fill out basic profile (name, bio, contact preferences) → Publish to directory
- **Why P0:** Enables the networking use case; without profiles, discovery feature is useless
- **Success Metric:** 85% of attendees created profiles, showing strong value proposition

**3. Browse & Connect with Other Attendees**
- **User Need:** Discover who else is attending and how to connect with them
- **Flow:** Navigate to attendee directory → Search/filter by name or interest → View profile → Exchange contact info
- **Why P0:** Solves the networking gap—no more missed connections
- **Success Metric:** Post-event survey showed 60% of attendees connected with at least 3 new people via the app

### P1 (Nice-to-Have) Journeys

**4. Leave Feedback**
- **User Need:** Share thoughts about the event and individual sessions
- **Flow:** Navigate to feedback section → Submit general event feedback or rate specific sessions
- **Why P1:** Important for organizers to iterate, but doesn't directly solve attendee pain points during the event
- **Future Enhancement:** Based on user feedback, 15% requested live session ratings—will prioritize in 2026 roadmap

## 📐 Design Principles

Based on user feedback ("we don't want complexity—we want something that just works"), the MVP followed these principles:

1. **Mobile-First:** Attendees are on-the-go; desktop is secondary
2. **Zero Onboarding Friction:** No account creation barriers—get to value immediately
3. **Real-Time Updates:** Agenda changes reflect instantly (no refresh needed)
4. **Discoverability Over Search:** Browse-friendly UI since users don't always know who they're looking for
5. **Lightweight:** Fast load times even on conference WiFi

## 🧰 Tech Stack

- **Platform:** Glide (web app builder)

**Why Glide?**  
As a solo founder with limited budget, Glide enabled rapid prototyping and deployment without the need for a full engineering team. This allowed me to validate the concept and achieve product-market fit before investing in a custom-built solution.

## 🎓 Product Lessons Learned

1. **Validate before building:** User interviews revealed attendees wanted simplicity, not feature bloat. This saved months of development time.

2. **Ship fast, iterate faster:** Launching an MVP with just 3 core features allowed me to gather real usage data and prioritize the roadmap based on actual user behavior, not assumptions.

3. **Constraints breed creativity:** Budget limitations led to a web-based solution that actually became a competitive advantage—faster iteration cycles and lower risk.

4. **Measure what matters:** Tracking adoption rate, missed sessions, and satisfaction gave me clear signals on product-market fit and informed the 2026 roadmap.
